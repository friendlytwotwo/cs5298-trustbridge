## 0. 这是什么

两个互不信任的自主 Agent（买方 Alice / 中介 Broker / 卖方 Bob）在 Lyquor 上完成一笔版权授权交易：
资金托管、通信哈希存证、LLM 估时的强制超时、四节点委员会裁决赔付全部链上强制执行。

三种运行方式，由浅入深：

| 模式 | 依赖 | 用途 |
|---|---|---|
| **sim**（进程内 FakeNode） | 仅 Python | 离线验证三条流程语义，无需 devnet |
| **node**（真实 devnet） | 7 容器 devnet | normal / timeout / adversarial 三条流真链上跑 |
| **committee**（node-only） | 7 容器 devnet + 新部署实例 | E2 四节点委员会认证流（演示核心亮点） |

## 1. 前置条件

- **Docker Desktop**（devnet = 7 个容器：`multi-tools` / `multi-node1-4` / `multi-registry` / `multi-anvil`）
- **Python 3.10+**，且 `pip install -r agents/requirements.txt`（唯一硬依赖 `requests`；sim 模式零依赖可先跑）
- **Git Bash**（Windows）或任意 bash；本仓库根目录 = `trustbridge/`
- devnet 栈定义在 LDK 仓库 `docker/multi/docker-compose.yaml`（LDK v0.8.1，锁定 rev `fd575e8`）

## 3. 启动 devnet（7 容器）

**已在跑**（本机当前状态）——验证：

```bash
docker ps --format "{{.Names}}\t{{.Status}}"
# 预期 7 行 Up：multi-tools / multi-node1-1 .. multi-node4-1 / multi-registry-1 / multi-anvil-1
```

**从零启动**（完整步骤见 `workflow-out/w1b1-topology.md`）：

```bash
# ① 若单节点 devnet 在跑，先停（host 10087 端口互斥）
cd <LDK 仓库> && docker compose -p ldk -f docker-compose.yaml down
# ② 起 4 节点 multi 栈（anvil + registry + node1-4 + setup-devnet bootstrap）
docker compose -f docker/multi/docker-compose.yaml up -d
# ③ 等 bootstrap 三步完成（bartender 幂等部署 → GetPeers≥3 → availability activate）
```

## 4. 部署 Lyquid 实例（每次演示前，新实例）

> 纪律：换源码必须重新 `docker cp`；`rm -rf` **必须带 `MSYS_NO_PATHCONV=1`** 前缀
> （否则 Git Bash 改写路径 → 容器内空删 → 旧源码残留，部署的是陈旧代码——B3 手册 §6-6 实测教训）。

```bash
cd trustbridge
# ① 清容器内旧源码并拷入当前源码
MSYS_NO_PATHCONV=1 docker exec multi-tools rm -rf /tmp/tb-lyquid
MSYS_NO_PATHCONV=1 docker cp lyquid/. multi-tools:/tmp/tb-lyquid

# ②（可选但推荐）容器内编译检查——要求 rc=0 / Finished
MSYS_NO_PATHCONV=1 docker exec multi-tools sh -c "touch /tmp/tb-lyquid/src/*.rs"
MSYS_NO_PATHCONV=1 docker exec -w /tmp/tb-lyquid multi-tools cargo check --target wasm32-unknown-unknown

# ③ 部署（私钥 = devnet 公开确定性 anvil#0 key，见 agents/common/rpc.py:97）
MSYS_NO_PATHCONV=1 docker exec -w /tmp/tb-lyquid multi-tools shaker deploy \
  -r http://registry:8000/lyquids --endpoint ws://node1:10087/ws \
  --private-key 0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80 Cargo.toml
```

部署成功尾部输出（T7 实录形态）：

```
Lyquid ID: Lyquid-<新实例名>
Contract: 0x<新合约地址>
```

**记下两个值**：实例名（`Lyquid-…`，`shaker console`/`to-hex` 用）和合约地址（`0x…`，demo `--contract` 用）。
备查：`MSYS_NO_PATHCONV=1 docker exec multi-tools shaker to-hex <实例名>` → oracle TARGET（42 字符，≠ 合约地址）。

## 5. 运行演示流程

### 5.1 正常流（报价 → LLM 评估 → 托管 → 交付 → 结算+中介费）

```bash
python scripts/demo.py --node http://127.0.0.1:10087 --contract 0x<合约地址> --flow normal
```

预期（T7/R1 实录形态）：`deal=deal-1` → `final state=Settled balances: alice=9000 bob=980 broker=20`
→ `DEMO COMPLETE`。LLM 评估当前为 **replay 模式**（确定性回放，`mode=replay` 字样；真实后端待 egress/凭据）。

### 5.2 超时流（卖方拖延 → watcher 提交 → 链上守卫复核 → 全额退款）

```bash
python scripts/demo.py --node http://127.0.0.1:10087 --contract 0x<合约地址> --flow timeout
```

node 模式内置 `nudge` 产块助推 + `claim_timeout`，一条命令跑完。
独立 keeper 守护（长驻轮询模式，对应 R2 实录）：

```bash
python scripts/keeper.py --node http://127.0.0.1:10087 --contract 0x<合约地址> --interval 5
# 缺省自动枚举到期 deal；--deals deal-N 可指定；--no-nudge 关闭产块助推
```

> 注意：已终态的 deal 重跑 keeper 只会输出 `"action": "terminal"`——claimed 事件是一次性的。

### 5.3 对抗流（伪造交付 → 争议 → 委员会裁决 Malicious → 退款+不端记录）

```bash
python scripts/demo.py --node http://127.0.0.1:10087 --contract 0x<合约地址> --flow adversarial
```

三个场景（Malicious 主场景 + Fulfilled/NotFulfilled 对照），预期 `DEMO COMPLETE`。
`--flow all` = normal + timeout + adversarial 三连。

### 5.4 委员会流 E2（⭐ 演示核心：四节点 oracle 认证裁决）

**必须用新部署实例**（arm/回合有单次纪律，见 §7）；`--instance` 传**实例名**（不是地址）：

```bash
python scripts/demo.py --node http://127.0.0.1:10087 \
  --contract 0x<合约地址> \
  --instance Lyquid-<实例名> \
  --flow committee
```

预期（T7 全绿实录 `_r3-t7-dt31-verify-raw.txt`，exit 0）：

```
[committee] TARGET=0x… (shaker to-hex …) != contract=0x… -> OK      ← 环境断言
[committee] node1..4 port=… node_id=Node-… bytes32=0x…              ← 四节点成员（GetNodeInfo 实取，禁硬编码）
[committee] faucet read-back OK: alice 0 -> 10000 (+10000)           ← D-T3-1 修复后新增
[committee] arm read-back OK: armed_deal == deal-1 (pre-arm='')
[committee] e2_run_verdict_round() -> True
[committee] final state=Refunded balances after={'alice': 10000, 'bob': 0, 'broker': 0}
[committee] refund check OK: alice 10000 -> 9000 (after fund) -> 10000 (after verdict); bob/broker unchanged
[committee] console evidence (source=node1, …): … 25 matching line(s) ← L2 判级（inputs=4 + signers=4）
DEMO COMPLETE
```

console 判级取证（只读、可单独重放，`timeout 60` 到点 rc=124 属正常收尾）：

```bash
MSYS_NO_PATHCONV=1 timeout 60 docker exec multi-tools shaker console <实例名> --endpoint ws://node1:10087/ws
```

关键判级行：`e2_aggregate: agreed deal=deal-1 verdict=1 from 4 input(s) (avg_num=4)` +
`cert.signers RAW = [0, 1, 2, 3]` + 四条 `signer N -> Node-…` 互异映射 → **L2（四节点全签）**。

## 7. 红线与单次纪律（违反即污染证据链）

1. **`e2_arm` / `e2_run_verdict_round` 每实例只发一次**——对已终态实例重发 = 证据失效；演示重跑 = 重新部署新实例。
2. **容器内命令必带 `MSYS_NO_PATHCONV=1`**（rm/cp/cargo/shaker 全部）。
3. `--instance` 传**实例名**不传地址；未传时 argparse 会回填上一次部署的缺省值——**开跑前核对输出首行 `instance =`**。
4. committee 流是 **node-only**：`--sim` 会 rc=1 退出（fail-closed，属预期）。
5. console 取证源 = node1；`timeout 60` 到点 rc=124 = 正常收尾，不是错误。
6. 画面不得露出完整私钥（`agents/common/rpc.py:97` 为 devnet 公开确定性密钥，展示时可打码）。

## 8. 常见问题（精选；全表见 `docs/b3-user-test/操作手册.md` §6，12 项）

| 症状 | 原因 | 处置 |
|---|---|---|
| `ModuleNotFoundError: No module named 'requests'` | 未装 Python 依赖 | `pip install -r agents/requirements.txt`（`agents/requirements.txt:4`） |
| `refund accounting mismatch`（T3 实录 :41） | **修复前**的 D-T3-1 缺陷（faucet 后立刻快照） | 已修复（T7 exit 0 重验）；若见于此说明跑的是旧代码，重新 `docker cp` + 部署 |
| committee 流 fail：TARGET 断言失败 | `--instance` 填了合约地址 | 传 `Lyquid-…` 实例名；`shaker to-hex` 验证 |
| 对已终态实例跑 committee | 未换新实例 | 重新 §4 部署新实例再跑 |
| `cast`/`shaker` 在宿主机找不到 | 这些工具只在 multi-tools 容器内 | 一律 `MSYS_NO_PATHCONV=1 docker exec multi-tools …` |
