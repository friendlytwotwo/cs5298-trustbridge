§2 部署阻塞与处置（plan 未预见；**登记性偏离**，详见 §6）
---------------------------------------------------------------------
首次 `shaker deploy` 在 solc 阶段失败（wasm 构建成功，SequenceBackend.sol 编译失败）：
  Error: Failed to compile SequenceBackend.sol: [Solc(Error { … message: "Compiler error
  (/solidity/libyul/backends/evm/AsmCodeGen.cpp:62): Stack too deep. … When compiling inline
  assembly: Variable dataEnd is 2 slot(s) too deep inside the stack. …" })]
定位（在生成的 solidity 上直接复现与二分，生成件路径
  /tmp/tb-lyquid/lyquid_tools_target/solidity/trustbridge/trustbridge.sol）：
  $ /root/.svm/0.8.37/solc-0.8.37 --optimize --optimize-runs 200 --evm-version paris --bin \
      --base-path . trustbridge.sol
  → 同一 Stack too deep（0.8.24 / 0.8.30 亦复现；0.8.19/0.8.21 无法解析该源，不适用）
  → 逐函数删除二分：删除 `assess_brief` 桩后 **exit=0 通过**（其余 28 个函数逐个删除均仍失败）
  → 桩签名变体测试：7×string 参数失败；6×string 参数通过；返回值改 bool/无返回仍失败
  ⇒ 平台侧 solc legacy codegen 对「≥7 个动态参数的单函数 ABI 桩」有栈深上限，
     assess_brief（7 个 string 参数）是唯一越限者，与 claim 探针无关。
处置（最小、可逆、语义零变化）：撤下 assess_brief 的 `export = eth` 属性
  （`#[method::instance(export = eth)]` → `#[method::instance]`，方法体/签名/assess 语义
  零改动，仓内无任何调用方）。撤下后重新部署即成功（§1）。此偏离为**持久保留**项，
  已写入 implementation.md 偏离登记；平台栈上限放宽后可原样恢复。
  另注：读通道 getter（deal_info / balance_of / due_deals / probe_claim_sim）不进入
  该生成件（读路径直连 Lyquid VM），因此本处置不影响任何读方法。

  G conservation  total=1000 == amount=1000 → true（四字段明细同列）
  H verdict    **PASS-full-refund 1000 -> 0xf39F…92266（now=caller:103）**

R4 停止条件核验：无 panic；caller_now≥deadline 且 F=Ok（非 Err）；G 勾稽一致 → 未触发停止。

§7 结论
---------------------------------------------------------------------
- 新镜像上 core::claim_timeout 路径 A→H 全程无 panic、无 Err：F=Ok(full_refund)、
  G 勾稽 true、H=PASS（now 来源=caller）。
- D1 根因闭环：旧实例 `0x1c85…` 的 `Barrel(FuncNotFound)`（balance_of/due_deals）在
  新实例消失；`chain_now` 在 eth_call 上下文 = 块高（≠0），排除「now=0 导致
  DeadlineNotReached 空 revert」假设。
- 遗留待办（非本轮目标）：println → 节点日志的通道不成立（仅 shaker console 可读），
  生产期定位建议以 console 附加或平台日志级别调整替代。
