§1 宿主工具链损坏与修复（G-init ③ 处置：修复 rustup 工具链）
-------------------------------------------------------------------------------
初始实测（与 plan §2-3 的规划期诊断一致，且比其记录更深一层）：
  $ ls -la ~/.cargo/bin/
    cargo.exe -> rustup.exe（rustup.exe 不存在；全部 shim 同为断链）
  $ ls ~/.rustup/toolchains/1.99.0-x86_64-pc-windows-msvc/bin/   # 仅 cargo.pdb
  $ ls ~/.rustup/toolchains/stable-x86_64-pc-windows-msvc/bin/   # rustc.exe 在，cargo.exe 缺失（仅 cargo.pdb）

修复步骤（全部实跑）：
  1) 从 rustup 官方 dist 装回 rustup（rustup-init，不改 PATH）：
     $ curl -s -o rustup-init.exe https://static.rust-lang.org/rustup/dist/x86_64-pc-windows-msvc/rustup-init.exe
     $ ./rustup-init.exe -y --no-modify-path --default-toolchain none
       ... info: skipping toolchain installation / Rust is installed now. Great!
     $ cargo --version → cargo 1.99.1 (5f94df478 2026-08-27)   # shim 复活
  2) 但首跑 cargo test 仍失败 —— 说明 rust-std 文件亦被删（比 plan §2-3 多一层损坏）：
     error: only metadata stub found for `rlib` dependency `core` ...
     error[E0463]: can't find crate for `std` ...
       = note: the `x86_64-pc-windows-msvc` target may not be installed
     实测 sysroot：libcore-f9527ed7f1165c0a.rlib 在，**libcore-...rmeta 缺失**（其余组件文件亦部分缺失）。
  3) rustup 不检测文件缺失（--force 无效）：
     $ rustup toolchain install stable --profile minimal --component rust-std --force
       info: component rust-std is up to date
       stable-x86_64-pc-windows-msvc unchanged - rustc 1.99.1 (58cf8f9c3 2026-10-13)
  4) 走**卸载重装**（plan T-init ③ 的 "重装 rustup / rustup toolchain install" 路径）：
     $ rustup toolchain uninstall stable
     $ rustup toolchain install stable --profile minimal
       info: latest update on 2026-10-15 for version 1.99.1 (58cf8f9c3 2026-10-13)
       info: downloading 3 components
         stable-x86_64-pc-windows-msvc installed - rustc 1.99.1 (58cf8f9c3 2026-10-13)
     $ ls ~/.rustup/toolchains/stable-.../lib/rustlib/x86_64-pc-windows-msvc/lib/libcore*
       libcore-f9527ed7f1165c0a.rlib
       libcore-f9527ed7f1165c0a.rmeta        # 已恢复
  结论：宿主 cargo 通道已可用（stable 1.99.1），未走容器路线（壳内 #[path] 保持宿主绝对路径原样）。
